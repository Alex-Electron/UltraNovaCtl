# Мутационный журнал ядра редактора

Зачем он есть. Зелёный набор проверок не доказывает, что проверки что-то защищают. В этом
проекте принято ломать рабочий код намеренно и смотреть, заметит ли набор. Здесь записано,
что именно ломали, что при этом падало, и — отдельно — где ломали и **не заметили**.

Дата прогонов: 09–12.09.2026. Способ одинаковый: подменить один фрагмент в `src/Core`,
собрать `tests/CoreRegressionTests`, прогнать, вернуть файл. Если набор остался зелёным —
это дефект проверок, а не удача.

⚠ Важно при повторении: **собирать заново обязательно**. Дважды за эти прогоны мутация
показалась «непойманной» только потому, что запуск шёл на несвежей сборке. Если результат
удивляет — сначала убедиться, что сборка прошла, и лишь потом делать вывод.

## Что закреплено мутациями

### `PatchProtocol` и `NrpnReader`

| что ломали | поймано |
|---|---|
| база смещений 13 → 12 | да, 2 проверки |
| контрольная сумма без циклического переноса | да |
| смещение имени патча 2 → 1 | да |
| заголовок перестал требовать терминатор `F7` | да |
| NRPN выдаёт данные без выбранного параметра | да |

### `ParameterCodec` и `ParameterDescriptor`

| что ломали | поймано |
|---|---|
| `floor(x+0.5)` → банковское округление | да, синтетическим дескриптором |
| флаг `Inverted` игнорируется | да |
| широкая пара байт перевёрнута на младший вперёд | да |
| упакованное поле пишется присваиванием байта, а не слиянием | да |
| знаковое значение без дополнительного кода | да |
| временный параметр пускают писать в патч | да |
| форматирование без проверки границ списка | да |
| широкое значение молча урезается в один байт | да |
| любое упакованное поле считается однобитным | да |

### `PatchModel`

| что ломали | поймано |
|---|---|
| модель держит массив вызывающего, а не копию | да, **после починки проверки** |
| свод ручки обратно в исходное значение всё равно пишется в историю | да |
| шаги отмены перестают склеиваться по смещению | да |
| новая правка не сбрасывает ветку повтора | да |
| непечатные символы попадают в имя | да, **после починки проверки** |
| запись того же значения создаёт шаг отмены | да, **после починки проверки** |

Три проверки из этого списка сначала мутации **не ловили**. Проверка копирования портила
рабочие байты, хотя подмена касается исходных; проверка имени читала имя обратно, а его
подчищает геттер; записи того же значения не проверял никто. Исправлены, см. коммит
`bf1af88`.

### `PatchFile`

| что ломали | поймано |
|---|---|
| любой 526-байтный SysEx принимается за патч | да |
| обрезанный хвост не измеряется | да |
| не-патчевый SysEx не считается пропущенным | да |
| перезапись существующего файла ломается | да |
| некорректные записи пишутся в файл | да, 2 проверки |

### `PatchSession`

| что ломали | поймано |
|---|---|
| грязный черновик затирается пришедшим патчем | да |
| `FollowPanel = false` перестаёт останавливать опрос | да |
| опрос идёт на каждое событие, а не один раз после паузы | да, 3 проверки |
| `KeepDraft` не забывает отложенный патч | да |
| освобождение оставляет подписку на движок | да, **после замены проверки на слабую ссылку** |

Одна мутация оставлена стоять **намеренно**: проверка `_disposed` внутри обратного вызова
таймера защищает от вызова, уже находящегося в полёте на момент освобождения. Детерминированно
это не воспроизвести, а сама проверка дешёвая, поэтому она остаётся без покрытия осознанно.

## Где мутациями не проверяли

Здесь набор зелёный, но это ничего не доказывает:

| слой | почему |
|---|---|
| `PatchMetadata` | не доходили руки; сообщение и таблицы покрыты обычными проверками |
| `EditorTransport` | пришёл из чужого захода; состязательное ревью нашло в его проверках пробелы и подтвердило их выжившими мутациями |
| `DeviceWatcher` | на приборе не подтверждён вовсе, мутации до аппаратной проверки смысла имеют мало |

### Пробелы, найденные ревью 11–12.09 и закрытые 12.09

Ревью доказало выжившими мутациями, что семь мест не закреплены ничем. Проверки написаны,
и те же самые мутации теперь падают:

| что ломали | поймано |
|---|---|
| transport enable подменён на повторный запрос статуса | да |
| detach перестал слать transport disable | да |
| 250-мс наблюдение за владельцем не взводится | да |
| метка `case 101` в отмене NRPN удалена | да |
| гейт поколения соединения удалён | да |
| снят гейт проверки сообщения метаданных | да |
| `Load` не отменяет взведённый опрос | да |

Наблюдение за владельцем проверяется **настоящим таймером**, а не вызовом `CheckOwnership`
вручную: ручной вызов как раз и прячет то, что взведения нет.
