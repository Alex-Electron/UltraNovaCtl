# Редактор: проверка ядра и следующий этап

Состояние на 2026-09-11. Основа — `main` / `7f30698`, последний локальный тег
`v1.2.2`. Описанные ниже изменения находятся в рабочем дереве, не выпущены.

## Что уже сделано

До этой проверки существовали приватный транспорт Port 1 (один читатель пина 6,
писатель 10), `PatchProtocol`, `NrpnReader`, `PatchModel`, `PatchFile`, `PatchSession`
и отдельный `DeviceWatcher`. Чтение и обратимая запись параметра подтверждены
предыдущими аппаратными сессиями; это не приёмка сегодняшних изменений.

Проверка 11 сентября закрыла следующие дефекты:

- `EditorTransport` сериализует отправки и проверяет владельца перед каждой из них.
  При появлении `NovaControlPluginHardwareLock` закрывает наш писатель без команды
  transport-disable, которая могла бы затронуть нового владельца. Дополнительная
  проверка выполняется каждые 250 мс. Ошибка проверки владельца запрещает отправку:
  для писателя используется строгая проба `IsHeldOrUnknown`; прежняя информационная
  `IsHeld` и поведение пересылки клавиатуры не изменены.
- Состояние Ready требует свежих статуса и дампа текущего edit buffer. Открытый пин
  сам по себе не означает готовность; отказ записи и таймаут синхронизации 5 секунд
  переводят соединение в Faulted. После уступки нужно явное новое подключение.
- Канал параметров берётся из статуса, сбрасывается при новой сессии. Старые
  отложенные запросы помечены поколением соединения и не уходят после переподключения.
- `PatchMetadata` проверяет 33-байтное сообщение, сохраняет все семь битов поля Flags,
  а не только Chord. Есть типизированное входящее событие и защищённый путь отправки.
  UI редактирования метаданных пока нет; входящее событие вызывает чтение свежего дампа.
- `PatchSession` не подменяет текущий черновик ответом на чтение банкового слота;
  отменяет отложенное чтение при отключении FollowPanel, загрузке файла и Dispose.
  При переданном `SynchronizationContext` обработка модели доставляется в него.
  Входящий массив копируется до отложенной обработки; MIDI-эхо не создаётся.
- `NrpnReader` не использует старый Data Entry MSB после нового выбора параметра
  и сбрасывает выбор NRPN при переключении на RPN.

Это защитный слой ядра, не готовый экран редактора и не полная защита от всех гонок
между процессами. Мьютекс может появиться между проверкой и фактической записью.

## Проверено

Из корня репозитория:

```powershell
dotnet build UltraNovaCtl.sln -c Release --no-restore -m:1
dotnet run --project tests/CoreRegressionTests -c Release --no-build
```

Результат: сборка успешна, 0 ошибок; 2 прежних предупреждения CS9057 — анализаторы
Avalonia ожидают более новый компилятор. Регрессионные проверки на момент этой записи:
**77/77 PASS**, включая восемь новых групп проверки редактора с подставным транспортом.
Число проверок растёт с каждым заходом — актуальное печатает сам раннер последней строкой,
и сверять надо с ним, а не с числом в документе.
Это не проверка USB-драйвера, UI или реального захвата устройства родным VST.
Повторная инкрементальная сборка также успешна; она может не повторять предупреждения
анализаторов. Проверены 34 локальные Markdown-ссылки; `git diff --check` не выявил
ошибок пробелов.

**Зеркало Obsidian не синхронизировано, вопреки прежней записи здесь.**
`research-tools/sync-obsidian-handover.ps1 -Check` завершается с ошибкой: в шапке зеркала
`Source SHA256` не совпадает с живым `HANDOVER.md`. Содержательно в зеркале нет блока
«Продолжать отсюда», который называет `OSC-FILTER-REQUIREMENTS.ru.md`, 107 уникальных ID
и `CC 58` для Pre-FX. Синхронизацию здесь намеренно не запускали: она пишет в личное
хранилище владельца, за пределами репозитория. Запустить её — отдельное решение владельца.

В исследовательской папке отдельно проходят **5/5** проверок workflow описи
(`node research-patch-editor/workflows/test-inventory-workflow.mjs`, из папки проекта).
Они проверяют сопоставление идентификаторов и отказ при неполных ответах;
не доказывают истинность всех результатов реверс-инжиниринга.

## Следующие работы, в порядке зависимости

1. **Закрыть полноту описи.** [Реестр](NATIVE-EDITOR-INVENTORY.ru.md) восстановлен,
   но замечания по девяти областям остаются открытыми. Отделить реальные действия
   пользователя от внутренних параметров, недоступного кода и особенностей оболочки.
2. **Довести жизненный цикл.** Подключить `DeviceWatcher` к владельцу соединения:
   остановка/освобождение при removal, ожидание стабилизации драйвера, новое рукопожатие
   при arrival. Устранить гонки Start/Stop/Attach и запретить редактору работать при
   fallback на публичный читатель. Добавить отдельный арбитраж панели
   `AutomapServerRunning`: наличие константы не является реализацией.
3. **Модель и локальный извлекатель.** Получать описания параметров из установленного
   Novation XML, не включать чужой полный реестр и картинки в дистрибутив. Проверять
   диапазоны, единицы, enum, bindings, известный дефект XML и подтверждённые поправки
   MIDI-адресов. Затем явные транзакции жестов/имени для Undo, baseline после сохранения,
   единая дисциплина потока модели, тесты конкурирующих/повреждённых `.syx` файлов.
4. **Первый законченный экран.** Oscillator/Filter, открытие/сохранение `.syx`,
   read/refresh, dirty-конфликт, Undo/Redo/Compare, состояние владельца и недоступности.
   Остальные страницы и библиотечные сценарии остаются обязательными для полной цели.
5. **Аппаратная приёмка и только затем выпуск.** Не публиковать текущую сборку как
   готовый редактор; не создавать тег без подтверждения владельца инструмента.

## Что требуется проверить на синтезаторе

- Оба порядка запуска с родным VST; открытие проекта Ableton с сохранённым патчем;
  скрытое окно VST; уступка без запроса/смены звука; явное возвращение с новым дампом.
- Родной Librarian и отдельно Automap Server: не считать мьютекс VST доказательством
  совместимости со всеми тремя программами.
- Физический USB replug во время чтения и при грязном черновике: нет зависания,
  старых команд, потери черновика и захвата публичного MIDI-входа Ableton.
- Смена канала прибора, чтение/правка с панели, проверка результата свежим дампом.
  Метаданные и неизвестные флаги — только с предварительно сохранённым оригиналом.
- Полный цикл сохранения/открытия и отмены. Запись в постоянный банковый слот,
  смена драйвера и прошивка не входят в автоматическую проверку.

`PatchModel` ещё не потокобезопасен сам по себе; UI обязан работать через выбранный
контекст. Семантика скрытого старшего бита genre для checksum остаётся исследовательским
вопросом. Конфликтные копии в `bin/obj` замечены в синхронизируемой папке: влияние
Yandex Disk на первоначальный сбой сборки вероятно, но причина не доказана.
