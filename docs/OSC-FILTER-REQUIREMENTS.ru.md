Сверено 2026-09-11 по официальному MIDI PDF, установленному XML и статическому
разбору нативных VST x64/x86. Это требования и доказательства, **не реализованный UI**.

## Объём первого экрана

Страница Oscillator содержит 79 узлов контролов, 97 привязок с неотрицательными ID
и 72 уникальных ID параметров. Filter — 46 узлов (45 `control` и один `group_control`),
53 привязки и 36 уникальных ID. Общий параметр — Envelope Track Note (160):
в объединении **107 ID**, а не 108 функций. Декоративные элементы и повторные
отображения не считаются отдельными возможностями. Привязки условий тоже учитываются,
поэтому число ID само по себе не доказывает наличие стольких независимых ручек.

| Блок | Пользовательские возможности | ID в локальном XML |
|---|---|---|
| Три осциллятора | Выбор waveform/wavetable/audio, pulsewidth/index, interpolation, virtual sync, hardness, density/detune, semitone/cents, bend range | 0–29 |
| Общие настройки осцилляторов | Vibrato rate/depth, drift, start phase, fixed note | 30–34 |
| Mixer | Тип шума; уровни трёх осцилляторов, двух ringmod и шума; pre/post-FX; шесть Solo | 35–49 |
| Голос | Unison voices/detune, portamento time/mode, pre-glide, polyphony | 433–438 |
| Amp envelope | ADSR, velocity, repeats, touch/mono-multi trigger, attack/decay slopes и tracking, sustain rate/time, level tracking | 70–84, общий 160 |
| Два фильтра | Частота, резонанс, envelope amount, keytrack, тип, distortion amount/type, Q-normalize | 50–65 |
| Совместная работа фильтров | Balance, шесть routing-режимов, частотная и резонансная связь, отображение маршрута | 66–69 |
| Filter envelope | ADSR и расширенные настройки, аналогичные amp envelope, с собственными диапазонами | 85–99, общий 160 |

Графики огибающих, выбор формы волны и схема маршрутизации должны оставаться
осмысленными отображениями состояния. Копировать старые картинки или координаты UI
не требуется. Не ограничивать огибающие четырьмя ADSR-ручками: дополнительные настройки
реально присутствуют на этих двух страницах.

## Расхождения и неочевидные правила

### 1. Pre-FX: не переносить ошибку PDF

На странице 2 PDF для Noise Type и Pre-FX Level напечатано CC 57.
XML строки 610–644 задаёт **Noise Type = CC 57, Pre-FX Level = CC 58**.
Кодировщик VST берёт CC из дескриптора; исключения для ID 42 в нём нет.
Следовательно, для совместимости с плагином выбираем CC 58. Это вывод из статических
источников; отдельный опыт изменения Pre-FX на приборе в этой проверке не выполнялся.

### 2. Отображаемое значение не равно байту MIDI

Кодировщик использует нормализованное значение и шкалу дескриптора:
`floor(start + range * normalized + 0.5)`, затем предусмотренное кодирование отрицательных
значений. В старых заметках пропущен вызов `floor`; он подтверждён по коду и строке
CRT `floor`. Нельзя автоматически превращать любое отрицательное значение на экране
в signed MIDI: сначала применяется нормализация конкретного параметра.

Проверяемые примеры из XML и формулы VST:

| Параметр | На экране | В MIDI |
|---|---|---|
| Osc1 cents | −50 / 0 / +50 | 14 / 64 / 114 |
| Pre-FX, dB | −12 / 0 / +18 | 52 / 64 / 82 |
| Osc1 semitone | −64 / 0 / +63 | 0 / 64 / 127 |

Границы, краткие подписи и enum берутся из установленного описания, а не угадываются
по диапазону MIDI 0–127. Обратное преобразование и округление требуют отдельных тестов
будущего продуктового кодека; текущая байтовая модель этого слоя не заменяет.

### 3. Связь фильтров — это не просто две галочки

XML хранит Freq Link и Res Link в одном program-байте 75, биты 0 и 1.
Правка одного бита должна сохранять второй и неизвестные биты. В MIDI родной редактор
меняет их через NRPN `0:122`: Freq Link значениями 42/43, Res Link — 44/45.
PDF описывает как общий CC 62 с упакованными флагами, так и механизм точечной записи
packed-полей; это два пути, а не повод посылать весь байт ради одной галочки.

При включённой частотной связи код VST перенастраивает параметр Filter2 Frequency:
диапазон отображения −64..63, подпись связи частот, сохранение нормализованного положения.
При резонансной связи XML строки 12561–12574 переключает правую ручку с ID 59
на ID 51: обе ручки управляют общим параметром. Нельзя оставить две независимые
ручки или только переименовать их. Подробное звучание режимов проверяется на приборе.

### 4. Solo — временное состояние, не байт патча

У шести Solo в XML `program offset=-1`, но есть NRPN `61:0..5`.
Не записывать их в дамп и не вычислять индекс массива из −1.
Хранить состояние отдельно; правила сброса при смене патча/отключении ещё проверить.
По PDF отправляемые значения — 0/127, принимаемый порог включения — 64.

### 5. XML требует контролируемого чтения

Найден **21 пропущенный разделитель атрибутов**: 20 повторений в списках modulation
destinations (`Chorus/Phaser4 Feedback`) и одно у слайдера AmpEnv Decay Slope,
строка 12087 (`spacing`/`direction`). Исследовательский скрипт проверяет точные шаблоны
и количество, исправляет только копию в памяти и сохраняет номера строк.
Будущий продуктовый извлекатель должен распознавать версию источника и сообщать
о неизвестных дефектах, а не молча применять неограниченный «починяющий» regex.

### 6. В остальных разделах есть поправки адресов

Код x64 и x86 подтверждает две специальные ветви: ID 448 получает `LSB + 1`,
ID 453–462 — `LSB + 16`. Эти 11 параметров не входят в первые две страницы,
но извлекатель нельзя проектировать как слепое копирование XML.

## Следующий небольшой шаг

Сделать семантический кодек для перечисленных типов данных **без подключения к прибору**:
обычный диапазон, диапазон со смещением, enum/bool, packed bit и transient Solo.
Проверить round-trip min/mid/max, сохранность соседних битов, общность ID 160,
отсутствие MIDI-эхо и корректную динамическую связь фильтров. Затем подключать этот
слой к черновику и UI, после проверки жизненного цикла соединения.

Этот аудит закрывает декларативную карту двух страниц и перечисленные участки VST.
Остальные области [общей описи](NATIVE-EDITOR-INVENTORY.ru.md), поведение всех жестов,
полная совместимость и аппаратная приёмка остаются открытыми.
